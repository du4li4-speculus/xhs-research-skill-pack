# XHS Research

这是一个研究型 Skill，不是运营/发帖 Skill。底层依赖 `xiaohongshu-mcp`。

## 核心原则

1. **图片必须真的看。** 不能把图片 URL 当作已经读取的内容。
2. 图文笔记调用 `get_feed_detail` 后，必须提取 `note.imageList[].urlDefault`，失败时回退 `urlPre`，并立即下载到本地。
3. 下载成功的图片必须逐张交给宿主的视觉模型理解；优先直接视觉理解，不以传统 OCR 作为默认方案。
4. 如果任一图片未成功下载或未被视觉模型读取，必须明确标记 `图片未读取`，不能根据标题、评论或上下文猜图中内容。
5. 视频默认只处理标题、正文、作者、发布时间、封面/静态图片信息。**默认不做视频下载、ASR、字幕转录和逐帧分析**，除非用户明确要求。
6. 研究结果保留来源身份：作者、发布时间、feed_id、内容类型、命中位置（正文/第几张图片/评论）。
7. 不把转发、二手复述或评论区猜测当成原始题目；对来源可信度做区分。

## 前置检查

先调用 `check_login_status`。

- 已登录：继续。
- 未登录：调用底层 MCP 的登录流程。
- 登录状态失效：停止研究并明确说明，避免输出伪结果。

## 路由 A：按博主研究

用户给出博主名，例如“XX托福”：

1. 使用 `search_feeds` 搜索博主名，可补充主题词（如 TOEFL、托福、雅思）。
2. 从结果中的作者昵称、头像、标题和内容方向识别候选账号。
3. 优先选择昵称完全匹配或高度匹配的账号；不要仅凭一篇转载内容认定账号身份。
4. 获取该作者的 `user_id` 与 `xsec_token` 后调用 `user_profile`，拉取公开笔记。
5. 再按用户要求的考试、科目、题型、日期窗口筛选候选笔记。
6. 候选不足时，再用 `search_feeds` 做关键词补检。

若同名账号无法可靠区分：返回候选，并按证据强弱标记，不要擅自合并账号。

## 路由 B：按主题/关键词研究

用户给出主题，例如“2026 TOEFL Build a Sentence”：

1. 设计 2–5 个搜索变体，例如：
   - TOEFL 2026 + Build a Sentence
   - 托福新题 + 句子构建
   - TOEFL 写作/语法 + 新题
2. 使用 `search_feeds` 搜索；优先使用与用户时间要求一致的 `publish_time` 和 `sort_by=最新`。
3. 合并候选，按 `feed_id` 去重。
4. 对高相关候选调用 `get_feed_detail`。

## 详情读取

调用 `get_feed_detail(feed_id, xsec_token)`，默认不加载全部评论。

先读取：
- `note.title`
- `note.desc`
- `note.type`
- `note.time`
- `note.user`
- `note.imageList`
- 必要时少量首屏评论用于来源验证

### 图文笔记：强制图片链路

当 `note.imageList` 非空：

1. 将完整详情 JSON 保存为临时文件，例如 `feed_detail.json`。
2. 调用本 Skill 附带脚本：

```bash
python scripts/download_xhs_images.py \
  --input feed_detail.json \
  --out-dir .xhs-cache/<feed_id>
```

3. 读取脚本生成的 `manifest.json`。
4. 对 `status=downloaded` 的每一张本地图片，使用宿主原生的 image/vision 能力逐张查看。
5. 图片很多时也不能只看首图。可先看缩略/顺序，但最终与研究结论有关的图片必须实际读取。
6. 记录每张图的：
   - image_index
   - local_path
   - 是否已视觉读取
   - 与研究问题相关的内容摘要

**禁止：** 仅根据 `urlDefault`、图片文件名、标题、正文或评论推测图片内容。

### 视觉提取标准

对于考试/教学资料，视觉模型重点提取：
- 考试体系：TOEFL / IELTS / SAT / ACT / A-Level 等
- 科目与题型
- 完整题干
- 选项、材料、对话角色、图表、限制条件
- 日期/场次/版本标识
- 图片中明确出现的来源或水印

如果图片只是封面、装饰或重复截图，要标记，不要把装饰性文字误当题目。

### 视频笔记：低成本默认

默认：
- 读取标题和正文
- 若详情里有静态封面/图片，可按图片链路读取
- 不下载视频
- 不做 ASR
- 不读取字幕地址
- 不抽帧

输出中标记：`视频音频/动态画面未分析`。

只有用户明确要求“视频也要完整提取”时，才另行启用视频处理能力。

## 内容判断与去重

对于“新题/考试资料”类任务：

### P0 原始/高可信
- 图片或正文直接展示完整题目
- 明确考试体系、题型和题干
- 多个独立博主出现相同题目可提高可信度

### P1 较可信
- 题目主体完整，但缺少少量上下文/选项
- 博主明确声称来自某场考试，且有部分原始内容佐证

### P2 线索
- 只有话题名称、回忆片段、评论区转述
- 不能还原完整题目

默认研究结果优先返回 P0/P1；P2 单独放在线索区，不能补写缺失部分。

去重时依据：
1. 题目语义主体
2. 关键题干/选项
3. 图片内容
4. 日期和题型

同一道题被多个博主发布时合并为一条，保留所有来源。

## 失败与质量控制

- `get_feed_detail` 失败：保留搜索结果，但不得宣称已读取全文或图片。
- 图片 URL 过期：重新调用 `get_feed_detail` 获取新地址后立即下载。
- 图片下载失败：可从 `urlDefault` 回退 `urlPre`；仍失败则标记未读取。
- 视觉模型无法辨认：标记“图片可见但局部不可辨认”，不要猜。
- 搜索没有结果：调整关键词、时间窗口、中文/英文变体，而不是编造不存在的账号或帖子。
- 评论量大时默认不全量加载；只有需要验证争议、补充线索或用户要求时才扩展。

## 成本控制

优先级：
1. 搜索结果元数据筛选
2. 候选详情正文
3. 与任务相关的图文原图视觉读取
4. 必要评论
5. 视频转录/逐帧分析（默认关闭）

研究目标是尽量把 token 和计算花在真正含信息的图片上。
